# Systems, economy and progression

## Systems that combine

- **Write rules, not encounters.** The chemistry engine of *Breath of the Wild*: a few *elements*
  (fire, water, ice, electricity, wind) act on *materials* (wood burns, metal conducts, ice melts),
  and everything follows the same rules. Every new element multiplies with every material, so play
  grows faster than content. Prefer a new rule that touches many things over a new thing that
  touches nothing.
- **Orthogonal options.** Each tool, weapon or unit should be best at something different (range,
  speed, area, armour piercing, mobility), not just a bigger number.
- **Complexity is a budget.** Each rule costs the player attention. Spend it where it buys the most
  decisions; cut rules that add reading but not choices.
- **Late mechanics.** Keep introducing new rules all the way through (new hazards, new materials,
  new movement) so the game keeps teaching.

## Economy

Map every resource as a flow:

- **Sources** (where it comes from: mining, drops, crops),
- **Sinks** (where it goes: crafting, repair, fuel, building),
- **Converters** (furnaces, crafting tables: one thing into another),
- **Stores** (chests, bag) and **traders**.

Checks:
- Every resource has at least one sink that the player wants. A resource that only piles up is noise.
- Sinks that keep working late (repair, fuel, building) keep early resources useful.
- Positive feedback (the rich get richer) speeds up a game; negative feedback (rubber banding, upkeep)
  keeps it close. Use positive feedback carefully in a long game; it ends challenge early.
- Consumables get hoarded unless the game pushes them forward: make them plentiful, make using them
  feel good, give them a shelf life or a natural reason to use now.

## Balance

- **Transitive** balance: better costs more (tiers). **Intransitive**: rock-paper-scissors, each
  beats one and loses to another. Tiers give progression; intransitive gives choices within a tier.
- **Input randomness** (the map, the loot you start with) makes the player plan; **output
  randomness** (a hit that misses at random) feels unfair if it decides outcomes. Prefer input.
- **Pity systems**: after a run of bad luck, raise the odds. Players feel streaks more than averages.
- Give numbers ranges, not points: tune by play, keep a table of the values.

## Progression

- **Gates**: a boss, a material or a tool that opens the next part of the world (Terraria's bosses
  and hardmode; metroidvania abilities). A gate should be visible before it can be passed, so the
  player has a goal.
- **Branches**: let the player choose between paths (Terraria's world evil; which boss first).
- **Nested goals**: the next small step is always visible, the next big one is on the horizon.
- **Power with a cost**: stronger things are heavier, slower, hungrier, or rarer; the player chooses
  a trade-off, not just an upgrade.
- **Meta-progression should add variety, not just power**: new options to play with, not bigger
  numbers that make the start trivial.
- **Graduated failure**: losing a fight costs a little (time, durability), dying costs more (a trip
  back), and only rare, chosen modes cost everything (hardcore).
- **Reward schedules**: fixed rewards are predictable; variable rewards are exciting but can be
  exploited. Use variable rewards for discovery (what's in the chest), fixed ones for effort
  (crafting always works).

## Procedural generation

- Seedable randomness: the same seed gives the same world, so challenges can be shared (a daily seed).
- Hand-made pieces (rooms, ruins) placed by rules give quality and variety together.
- Guarantee the essentials near the start (wood, stone, water, a cave) so a bad roll never ruins
  the first night.
